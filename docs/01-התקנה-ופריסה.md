## עדכון קוד (אחרי כל שינוי בתיקייה apps-script)
התיקייה `apps-script/` במחשב היא העותק של מה שנמצא בפרויקט ב-Google: `Code.gs` ו-`Index.html` (שבפרויקט נקרא `Index`).
**הקוד נפרס ל-Google רק מ-`main`**, אחרי שהענף של היכולת מוזג אליו (ראו "עבודה עם GitHub" בהמשך). לא מדביקים ל-Google קוד שנמצא רק בענף.
1. מריצים את הבדיקות ומוודאים שכולן עוברות (ראו [בדיקות ואבטחה](04-בדיקות-ואבטחה.md)), ומוודאים שהקוד במחשב הוא `main` אחרי המיזוג.
2. פותחים את הפרויקט ב-script.google.com, בחשבון arcobalenochic@gmail.com.
3. בקובץ `Code.gs` מוחקים הכול (Ctrl+A) ומדביקים את התוכן של `apps-script/Code.gs`. עושים אותו דבר בקובץ `Index` עם `apps-script/Index.html`, אם הוא השתנה.
4. שומרים (Ctrl+S).
5. **פריסה** ← **ניהול פריסות** ← עיפרון ליד הפריסה הקיימת ← **גרסה: גרסה חדשה** ← **פריסה**.

הכתובת לא משתנה. אם יוצרים "פריסה חדשה" במקום לערוך את הקיימת, נוצרת כתובת חדשה והקישורים הישנים יפסיקו לקבל עדכונים.

**אם כתובת המערכת משתנה בכל זאת:** מעדכנים את `MAIN_URL` בראש `apps-script-sender/Code.gs` ופורסים גם את השולח. אחרת השולחים של אנשי ההנהלה לא ימצאו את המערכת. בדיקה סטטית מתריעה על אי-התאמה מול `config/deployment.json`.

## עדכון השולח האישי (אחרי שינוי בתיקייה apps-script-sender)
אותו תהליך (גם כאן, רק מ-`main`), בפרויקט "קול הסטודנטים - שולח המיילים האישי": מדביקים את `apps-script-sender/Code.gs` (ואת `appsscript.json` אם השתנה), שומרים, ופורסים **גרסה חדשה של הפריסה הקיימת**.
- אם הכתובת של השולח משתנה, מעדכנים את `SENDER_URL` ב-`apps-script/Code.gs` ופורסים גם את המערכת.
- אם משנים את רשימת ההרשאות (`oauthScopes`), כל איש הנהלה יצטרך לחבר מחדש.

## בדיקת השולח האישי מהעורך
שימושי כשהדפדפן מחובר לכמה חשבונות Google, ולכן לא פותח את דפי המערכת:
1. בפרויקט המערכת מריצים `testPersonalSender`. ביומן הביצוע מופיע כרטיס חיבור, תקף ל-10 דקות.
2. בפרויקט השולח: **הגדרות הפרויקט** ← **מאפייני סקריפט** ← מוסיפים `TEST_TICKET` עם הכרטיס.
3. בפרויקט השולח מריצים `connectFromEditor`. בפעם הראשונה Google מבקשת אישור. ביומן מופיע `"connected":true`.
4. מריצים שוב `testPersonalSender` במערכת: מייל בדיקה נכנס לתור.
5. מריצים `tick` בשולח (או מחכים עד 10 דקות). המייל מגיע לתיבה, ויוצא מהחשבון שלך.
6. לסיום אפשר לנתק: מריצים `disconnect` בשולח.

## איפוס משתמשים (כדי לבדוק את המערכת מההתחלה)
בעורך בוחרים את הפונקציה `resetUsers` ולוחצים **הפעלה**. מריצים אותה רק אחרי שהקוד העדכני הודבק ונשמר.

**מה נמחק:**
- השמות של כל המשתמשים.
- כל הכניסות. כולם מנותקים מיד, מכל מכשיר.
- אנשי ההנהלה של כל הקורסים.
- רשימות המשתתפים. הגבלת "רק מהרשימה" מבוטלת, כדי שאף אחד לא יינעל בחוץ.
- בקשות ההרשאה.
- הרישום של מי נכנס לאיזה קורס.
- החיבורים של השולחים האישיים, ומיילים שעוד ממתינים להם. כל שולח מחובר מפסיק לפעול מעצמו בסבב הבא, ומוחק את הטיימר שלו.

**מה נשאר:** הקורסים, הפניות של הסטודנטים, המענים, הניתוחים והעותקים. סטודנט שנכנס שוב עם אותו מייל יראה את הפניות שלו.

**מנהל המערכת** אחרי האיפוס הוא רק בעל הסקריפט (arcobalenochic@gmail.com). גם הוא יתבקש שוב לכתוב שם בכניסה הבאה.

**לפני המחיקה** נשמר גיבוי בתיקיית "קול הסטודנטים – קבצים" ב-Drive, בשם "גיבוי משתמשים לפני איפוס - <תאריך>.json". הגיבוי לא כולל את קודי הכניסה.

### איפוס מלא, כולל הפניות
הפונקציה `resetEverything` עושה את כל מה ש-`resetUsers` עושה, ומוחקת גם את כל המשוב:
- הפניות והמענים.
- הניתוחים והמענים לנושאים.
- העותקים השמורים.
- הקבצים שהועלו. הם עוברים לפח של Drive, ואפשר לשחזר אותם במשך 30 יום.

**מה נשאר:** רק הקורסים עצמם, עם אותם קישורים.

**הגיבוי** נשמר בשם "גיבוי מלא לפני איפוס - <תאריך>.json".

## התקנה מאפס (לחשבון אחר או לגיבוי)
1. ב-https://script.google.com לוחצים **פרויקט חדש** וקוראים לו "קול הסטודנטים".
2. מדביקים את `apps-script/Code.gs`. מוסיפים קובץ **HTML** בשם `Index` (בלי סיומת) ומדביקים בו את `apps-script/Index.html`.
3. בוחרים את הפונקציה `setup` ולוחצים **הפעלה**. מאשרים את ההרשאות: **Advanced** ← **Go to קול הסטודנטים (unsafe)** ← **Allow**.
   הפונקציה יוצרת את גיליון הנתונים ואת תיקיית הקבצים, וקובעת את בעל החשבון כמנהל המערכת.
4. מוסיפים את מפתח Claude (ראו [מפתח Claude](02-מפתח-Claude.md)).
5. **פריסה** ← **פריסה חדשה** ← גלגל שיניים ← **אפליקציית אינטרנט**. הפעלה בתור: **אני**. למי יש גישה: **כולם**. לוחצים **פריסה** ומעתיקים את הכתובת.
6. נכנסים לכתובת עם המייל של בעל החשבון ויוצרים קורס.
7. **השולח האישי:**
   - פרויקט חדש בשם "קול הסטודנטים - שולח המיילים האישי".
   - ב**הגדרות הפרויקט** מסמנים "הצגת קובץ המניפסט appsscript.json".
   - מדביקים את `apps-script-sender/Code.gs` ואת `apps-script-sender/appsscript.json`. ב-`MAIN_URL` שמים את הכתובת מסעיף 5.
   - **פריסה חדשה** ← **אפליקציית אינטרנט**. ההגדרות (המשתמש שניגש, כל בעל חשבון Google) כבר באות מהמניפסט.
   - את הכתובת שמים ב-`SENDER_URL` ב-`apps-script/Code.gs`, ופורסים שוב את המערכת.

## הגדרות (מאפייני סקריפט)
בעורך: גלגל שיניים (**הגדרות הפרויקט**) ← **מאפייני סקריפט**.

| מאפיין | מה זה | נוצר |
|---|---|---|
| `ANTHROPIC_API_KEY` | מפתח Claude API | ידנית |
| `ADMIN_EMAILS` | מנהלי מערכת, מופרדים בפסיק | אוטומטית ב-setup |
| `CLAUDE_MODEL` | מודל לשימוש. ברירת מחדל: `claude-opus-5-5` | לא חובה |
| `SESSION_EPOCH` | משתנה בכל איפוס משתמשים, ומנתק את כל הכניסות | אוטומטית ב-`resetUsers`. לא לשנות |
| `SHEET_ID`, `FOLDER_ID`, `FOLDER_<קורס>` | מזהי הגיליון והתיקיות | אוטומטית |
| `SECRET` | מפתח פנימי לספירת סטודנטים אנונימיים | אוטומטית. לא לשנות |

בפרויקט השולח האישי אין מאפיינים קבועים. `TEST_TICKET` משמש רק לבדיקה מהעורך, ונמחק מעצמו אחרי שימוש אחד.

## גיבוי הפרויקט וחזרה לגרסה קודמת
ההיסטוריה ב-Git היא הדרך העיקרית לחזור לגרסה קודמת. בנוסף, כגיבוי מקומי, אחרי כל שינוי בקבצי הפרויקט ה-hook שומר עותק מלא בתיקייה `backups/` (נשארת במחשב בלבד, לא ב-GitHub). הרשימה עם התאריכים נמצאת ב-`backups/גרסאות.md`.
- **לראות את הגרסאות:** `powershell -NoProfile -ExecutionPolicy Bypass -File tools\restore-backup.ps1`
- **לחזור לגרסה:** אותה פקודה עם `-Name <שם הקובץ>`. למשל, הגרסה שלפני השולח האישי היא `2026-10-27_10-28-49_קבוע.zip`.
- **לפני שחזור** נשמר עותק של המצב הנוכחי, כך שאפשר לחזור גם מהשחזור.
- **אחרי שחזור** פורסים שוב את הקוד ל-Google (סעיפי העדכון למעלה). רק אז השחזור מגיע למערכת החיה.
- **גיבוי ידני עם שם:** `powershell -NoProfile -ExecutionPolicy Bypass -File tools\backup.ps1 -Label "שם" -Keep`
